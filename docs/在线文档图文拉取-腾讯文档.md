# 腾讯文档问题表：图文拉取手册

把[开发问题记录](https://docs.qq.com/sheet/DTXdheFhaZ3VIWWdB?tab=BB08J2)里某一天的问题（文字 + 原图）拉到仓库独立目录。本文是 8.27 / 9.2 / 9.4 / 9.7 几次实操后的完整做法。

## 1. 目标产物

按日期建目录，不要往旧批次里混：

| 目录 | 对应表格日期 |
|------|----------------|
| `docs/dev-issues/` | 2026年8月27日（首批） |
| `docs/dev-issues-2026-09-02/` | 2026年9月2日 |
| `docs/dev-issues-2026-09-04/` | 2026年9月4日 |
| `docs/dev-issues-2026-09-07/` | 2026年9月7日 |
| `docs/dev-issues-2026-09-08/` | 2026年9月8日 |
| `docs/dev-issues-2026-09-09/` | 2026年9月9日 |

每个目录固定三样：

```
docs/dev-issues-YYYY-MM-DD/
  README.md          # 目录表 + 每条描述和本地截图
  issues.json        # 结构化数据（含原图 URL、表格行号）
  images/
    issue-01-img1.png
    issue-04-img2.png   # 一条多图按 img1、img2、img3…
```

同一天下午又加了行：只 **追加** 新行，不要改已有编号和已下好的图。

## 2. 为什么不能 curl / 公开 API

无登录态时这些路都走不通：

| 尝试 | 结果 |
|------|------|
| `GET https://docs.qq.com/sheet/DTXdheFhaZ3VIWWdB?tab=BB08J2` | 只有壳页面，没有单元格 |
| `dop-api/opendoc?padId=…` | `retcode=200026`，`isLogin=false`，空白文档 |
| `dop-api/get/sheet?padId=DTXdheFhaZ3VIWWdB` | `ProPadMeta is empty` |
| `/export?format=xlsx` | 返回登录 HTML，不是 xlsx |
| Chrome `get_network_request` 把 sheet JSON 存到新目录 | 可能报 workspace root 拒绝，别依赖这条 |

真正有数据的接口（登录后可见）类似：

```
GET https://docs.qq.com/dop-api/get/sheet
  ?padId=300000000$MwaxXZguHYgA
  &subId=BB08J2
  &startrow=0&endrow=-1&outformat=1&nowb=1
```

响应里的 `data.initialAttributedText.text` 是压缩包，解析成本高。稳定做法是：**用已登录的 Chrome 页，直接读表格运行时对象**。

## 3. 前置条件

1. Cursor 已接 **Chrome DevTools MCP**（本仓库会话里是 `user-chrome-devtools`）。
2. 该 Chrome 里已经登录腾讯文档，能打开上面的表格（只读即可）。
3. 本机有 Python 3，以及能读 PNG 尺寸的库（验证用 `Pillow`）。
4. **不要**把 Cookie、TOK、fingerprint 写进仓库。脚本用环境变量 `QQ_DOC_COOKIE`。

表格身份：

- 文档 URL id：`DTXdheFhaZ3VIWWdB`
- 工作表 tab：`BB08J2`
- 运行时 padId：`300000000$MwaxXZguHYgA`（以页面为准）

## 4. 表格列约定

数据从第 1 行开始（第 0 行是表头）。`getCellDataAtPosition(r, c)` 行列都是 0 起算。

| 列 | 字段 | 说明 |
|----|------|------|
| A / 0 | 日期 | 精确字符串，如 `2026年9月7日`，不要写成 `9.7` |
| B / 1 | 所属端 | `平台端` / `小程序端` / `买手PC端&ipad` |
| C / 2 | 模块 | 如 `订单详情` |
| D / 3 | 描述 | 可能为空，以截图为准 |
| E–G / 4–6 | 截图 | 每格 0 或 1 张；一条最多 3 张，从左到右 |
| H / 7 | 状态 | `待确认` / `已解决` / `已完成` |
| I / 8 | 原因 | `逻辑不对` / `编码问题` / `未按原型` / `功能缺陷` / `字段缺失` |

图不是单元格显示文字，而是 `cell.extendedValue`：一段 JSON 字符串，解析后是 URL 数组。

**原图 URL（要这个）：**

```
https://docimg10.docs.qq.com/image/AgAABmAdFux….png?w=1565&h=877
```

**缩略图 URL（不要这个）：**

```
https://docimg10.docs.qq.com/image/AgAABmAdFux….png?imageMogr2/thumbnail/200x89/ignore-error/1
```

`?w=&h=` 就是原图像素。本地 PNG 必须和这两个数一致。小程序截图宽约 400px、PC 约 1300–1800px，都是原图，不是压缩失败。

## 5. 全量拉取（某一天的全部行）

### 5.1 打开表格

```
list_pages
new_page  url=https://docs.qq.com/sheet/DTXdheFhaZ3VIWWdB?tab=BB08J2  timeout=60000
```

等到 `SpreadsheetApp` 就绪（`wait_for` 对表格引擎没用，用脚本轮询）：

```javascript
() => !!(window.SpreadsheetApp
  && window.SpreadsheetApp.workbook
  && window.SpreadsheetApp.workbook.worksheetManager)
```

返回 `true` 再抽数。页面上有「登录腾讯文档」按钮说明没登录，停下来，不要用空表硬抽。

### 5.2 抽出指定日期的行

把日期改成当天，例如 `2026年9月7日`。先扫一遍日期计数，确认当天行数，避免漏掉表尾新行。

```javascript
() => {
  const sheet = window.SpreadsheetApp.workbook.worksheetManager.getSheetBySheetId('BB08J2');
  const rows = sheet.getRowCount();
  const cols = Math.min(sheet.getColCount(), 9);
  const TARGET = '2026年9月7日';
  const out = [];
  const dates = {};
  const getText = (cell) => {
    if (!cell) return '';
    const fv = cell.formattedValue && (cell.formattedValue.value || cell.formattedValue);
    return (typeof fv === 'string' ? fv : (cell.value != null ? String(cell.value) : '')).trim();
  };
  for (let r = 1; r < rows; r++) {
    const date = getText(sheet.getCellDataAtPosition(r, 0));
    if (date) dates[date] = (dates[date] || 0) + 1;
    if (date !== TARGET) continue;
    const cells = [];
    for (let c = 0; c < cols; c++) {
      const cell = sheet.getCellDataAtPosition(r, c);
      if (!cell) { cells.push(null); continue; }
      const text = getText(cell);
      let imgs = [];
      const ext = cell.extendedValue;
      if (typeof ext === 'string' && ext.includes('http')) {
        try {
          const parsed = JSON.parse(ext);
          if (Array.isArray(parsed)) {
            imgs = parsed.filter(x => typeof x === 'string' && x.startsWith('http'));
          }
        } catch (e) {}
      }
      cells.push({ text, imgs });
    }
    out.push({ r, cells });
  }
  return { totalRows: rows, dateCounts: dates, count: out.length, data: out };
}
```

要点：

- 只收 `startsWith('http')` 的字符串，丢掉表格内部对象。
- E/F/G 都要扫；第 3 张图经常在 G 列。
- 记下 `r`（表格行号），写进 `issues.json` 的 `sheetRow`，追加时靠它去重。
- 描述空、图也空都原样保留，不要猜。

### 5.3 取 Cookie

同一页执行：

```javascript
() => document.cookie
```

立刻用于下载，不要提交、不要写进 md。Cookie 里常见 `TOK`、`hashkey`、`fingerprint`、`ES2`。过期后原图会 403 或下到 HTML。

### 5.4 建目录、落盘

PowerShell：

```powershell
New-Item -ItemType Directory -Force -Path "E:\angsa\angsa_data\项目\Roomroom\docs\dev-issues-2026-09-07\images" | Out-Null
```

把抽出的行写进一次性 Python 脚本（PowerShell 对 `python -c` + f-string 很容易解析炸，**必须写成 .py 文件**）。脚本职责：

1. 行 → `issues[]`（`id` 从 1 起，按表格从上到下）。
2. 图 URL 按 E→F→G 去重保序。
3. 文件名 `issue-{id:02d}-img{n}.png`。
4. 用 Cookie + `Referer: https://docs.qq.com/sheet/DTXdheFhaZ3VIWWdB?tab=BB08J2` 下原图。
5. 写 `issues.json` 和 `README.md`。
6. 已存在且 size > 0 的 PNG 跳过。
7. 响应小于约 200 字节当失败（多半是登录页）。

下载头：

```python

    "User-Agent": "Mozilla/5.0",

    "Cookie": os.environ["QQ_DOC_COOKIE"],

```

跑脚本（Cookie 只放环境变量）：

```powershell

python "E:\angsa\angsa_data\项目\Roomroom\docs\dev-issues-YYYY-MM-DD\export-issues.py"
```

### 5.5 `issues.json` 字段

```json
{
  "source": "https://docs.qq.com/sheet/DTXdheFhaZ3VIWWdB?tab=BB08J2",
  "title": "开发问题记录",
  "exportedAt": "2026-09-07",
  "issues": [
    {
      "id": 1,
      "sheetRow": 94,
      "date": "2026年9月7日",
      "client": "平台端",
      "module": "订货会预约列表",
      "desc": "…",
      "status": "待确认",
      "reason": "逻辑不对",
      "images": ["https://docimg….png?w=1531&h=911"],
      "files": ["issue-01-img1.png"]
    }
  ]

```

`images` 与 `files` 按下标一一对应。无图时两个数组都是 `[]`。

### 5.6 `README.md` 结构

1. 标题：`# 开发问题记录（YYYY-MM-DD）`
2. 来源链接 + tab `BB08J2`
3. 一句汇总：条数、是否全待确认、哪几条原文无图
4. 总表：`# | 所属端 | 模块 | 描述 | 原因 | 图`
5. 每条独立一节：

```markdown
## 1. 模块 — 描述原文

- 提出时间：2026年9月7日
- 所属端：平台端
- 模块：订货会预约列表
- 状态：待确认
- 原因：逻辑不对
- 表格行：94

**描述**

…

**截图**

图1：

![订货会预约列表 图1](images/issue-01-img1.png)
```

无图写：`_原文无截图。_`  
描述单元格为空：写明空，并指向截图，不要编造文案。

## 6. 增量拉取（同一天又加了行）

1. 再打开表格，用同一脚本抽出 **当天全部行**。
2. 读已有 `issues.json`，收集 `sheetRow`。
3. 只处理 `sheetRow` 不在集合里的新行。
4. 新 `id` = 现有最大 id + 1、+2…（例如 9.7 原先 1–11，新行是 12–14）。
5. 只下载新图；旧 PNG、旧 id、旧描述不动。
6. `issues = existing + new`，整份重写 README（总表要包含新旧全部）。
7. 不要因为表格里旧行状态改成「已完成」就改本地旧记录，除非明确要求同步状态。

去重键是 **`sheetRow`**，不是描述文本。不同端常有几乎相同的文案。

## 7. 验收（每次必做）

用短脚本核对，不要只看下载成功日志。

| 检查 | 通过标准 |
|------|----------|
| 条数 | 与表格当天 `count` 一致 |
| PNG 数量 | 等于所有 `files` 之和 |
| 缺失 / 多余 | 都是 none |
| 像素 | `PIL.Image.open(p).size` 等于 URL 的 `w`×`h`，全部匹配 |
| 缩略图 | URL 里不能出现 `thumbnail` / `imageMogr2` |
| 对应关系 | 抽数结果里的描述、模块、URL 与本地 `issues.json` 再对一遍 |

抽数脚本可再跑一次，只返回 `{r, module, desc, imgs}`，和 `issues.json` 逐行 diff。

抽查分辨率时：PC 图应是千级像素；小程序图约 400×770。若 PC 图也只有一两百宽，说明下成缩略图了，删掉重下原链。

## 8. 收尾

1. 删除一次性 `export-issues.py`、`append-new.py`、`_check_images.py`。
2. 不要把 Cookie、探测脚本、`sheet-raw.json` 留在仓库。
3. 目录里最终只留 `README.md`、`issues.json`、`images/*.png`。

## 9. 实操踩坑

1. **没登录态抽到的是空工作簿。** 先看页面标题和是否有登录按钮。
2. **网络面板里的图很多是 toolbar SVG 和 `thumbnail/200x`。** 不要按下图列表当原图。
3. **一条问题多图必须按 E→F→G。** 对调 img1/img2 等于串图。
4. **表格可见区域不是全部行。** 用 `getRowCount()` 扫全表，不要只截当前屏。
5. **用户截图往往只露前几条。** 9.2 当时屏上 9 条，表里实际 15 条；以抽数为准。
6. **无图是合法状态。** 9.4 第 8 条买手 PC「品牌详情 / 延续款」原文就没图。
7. **原图要带 Cookie。** 裸 `urllib` 常失败或下到登录 HTML。
8. **PowerShell 里不要 `python -c` 拼长脚本。** 写成文件再跑。
9. **`evaluate_script` 的返回值必须能 JSON 序列化。** 不要把 DOM / 函数扔回来。
10. **日期用单元格原文。** `2026年9月7日` 和 `2026-09-07`、`9.7` 对不上。
11. **追加时不要重排 id。** README、口头编号、后续改 bug 都按第一次编号。
12. **Chrome 重启后 pageId 会变。** 每次先 `list_pages`。
13. **MCP 把响应存到新建目录可能被拦。** 数据走 `evaluate_script`，文件走本机 Python。

## 10. 标准流程清单

新的一天：

1. `new_page` 打开表格，确认已登录且 `SpreadsheetApp` 就绪。
2. 抽日期计数，锁定目标日期行。
3. 抽出 `{r, cells}`（含图 URL）。
4. 取 `document.cookie`。
5. 建 `docs/dev-issues-YYYY-MM-DD/images/`。
6. Python 下载原图、写 `issues.json` / `README.md`。
7. 像素 + 条数 + 无多余/缺失 验收。
8. 删一次性脚本。

同一天补行：

1. 再抽当天全部行。
2. 用 `sheetRow` 找出新增。
3. 从 `max(id)+1` 追加，只下新图，重写 README。
4. 再验收全量（含旧图，确认没被覆盖）。

def collect_images(cells):
    urls = []
    for cell in cells[4:7]:
        if not cell:
            continue
        for url in cell.get("imgs") or []:
            if url and url not in urls:

    return urls
