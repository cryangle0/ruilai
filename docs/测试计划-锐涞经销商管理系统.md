| 项 | 内容 |
|---|---|
| **版本** | v1.0（2026-09-02） |
| **范围** | 已开发并部署的 Web 管理后台、微信小程序、Java API、演示数据与 RBAC |
| **线上环境** | Web：`https://label.onnsa.cn/ruilai/` · API：`https://label.onnsa.cn/ruilai-api` · 健康检查：`GET /api/health` |

---

## 1. 测试目标

1. **功能正确**：各角色在 Web / 小程序能完成授权范围内的业务操作，数据状态与 Excel/原型规则一致。
2. **权限隔离**：RBAC 菜单、路由、写接口按 `sys_role.perms` 生效，有限角色不能越权。
3. **链路闭环**：采购 → 入库 → 销售/激活 → 库存 → 退货 → 异常 → 统计，关键节点可追踪到 SN 与操作日志。
4. **演示可持续**：测试不破坏长期演示数据（双人会签未完成、金华待分配、温州待审、admin 主账号等）。
5. **可回归**：每次发版可按本计划「冒烟 + 核心链路 + RBAC」快速复验。

## 4. 测试工具与方法

### 4.1 Web 管理后台

- **推荐**：Chrome + DevTools（或 Cursor `user-chrome-devtools` MCP）
- **步骤模板**：
  1. 登录指定账号
  2. 侧栏逐页进入（记录可见菜单）
  3. 列表：搜索/重置/Tab/分页
  4. 点行 → 详情/抽屉 → **取消**（不写库）
  5. 核对 URL query（`l1Id`、`l2Id`、`tab`、`from`、`to`、`back`）
  6. 有 `back` 的页面点「返回」回到来源详情
  7. 截图或填检查表

### 4.2 微信小程序

- 微信开发者工具 + 真机预览（NavBar 固定、TabBar 需真机或模拟器验证）
- Agent / 脚本接模拟器：见仓库根目录 `docs/微信开发者工具-小程序联调指南.md`（`wechatide` CLI/MCP，不要用 Chrome CDP）
- 按 Tab：**首页 / 业务 / 库存 / 售后 / 我的** 及分包页
- 扫码类：准备演示 SN 或扫码枪；无硬件可用 API 辅助验证

### 4.3 API（可选自动化）

```bash
# 登录示例（Python / curl 均可）
POST /api/auth/login
{ "username": "admin", "password": "demo", "client": "web" }

# 带 Token
GET /api/roles
Authorization: Bearer <token>
```

- 403 时检查 `message` 与 HTTP 状态码
- 写操作测试在**测试库**或「打开即取消」策略下进行

### 4.4 日志与闭环验证

| 验证点 | 位置 |
|---|---|
| 操作日志 | Web → 系统 → 操作日志（`admin`） |
| SN 生命周期 | Web → SN 码库 → 点行 → 完整流转 |
| 库存流水 | Web → 库存管理 → 行详情 |
| 通知 | Web 顶栏通知铃铛 |

## 8. 端到端业务闭环（P1，建议每轮选 2 条）

### 8.1 链路 A：一级采购入库（小程序 → Web 会签）

```
agent_hd 小程序建 PO
  → admin Web 采购列表 pending
  → （测试环境）admin 会签段号匹配 → approved
  → SN 入库一级在库
  → 库存流水 + SN 事件「入库」
  → 操作日志有记录
```

**闭环检查点**：PO 状态、SN `status=l1`、库存汇总、日志。

### 8.2 链路 B：分销出货（L1 扫码）

```
agent_hd 建分销 SO
  → hd_scan_01 扫码（不可 confirm）
  → agent_hd 扫码至 planTotal
  → confirm
  → SN bound/l2，库存变化
  → Web 销售单详情一致
```

### 8.3 链路 C：直销激活（L2）

```
agent_hz 直销绑定/激活
  → SN 已销售 + 客户信息
  → Web 客户/SN 可查
  → 异常（若触发）可在 Web 处理
```

### 8.4 链路 D：退货

```
L2 或用户退（小程序）
  → L1 自动通过 / 平台审（视类型）
  → SN 标签「已退货/再入库/已冻结」
  → 返货 Web 列表状态
  → 库存流水
```

### 8.5 链路 E：RBAC 回归

```
admin 改运营专员权限（取消 purchase）
  → ops 重新登录
  → 侧栏无采购
  → GET/POST 采购 API 403
  → 恢复权限后再验 200
```

## 9. 缺陷管理与测试闭环

### 9.1 缺陷分级

| 级别 | 定义 | 处理 SLA（建议） |
|---|---|---|
| **S1 阻塞** | 无法登录、核心链路全断、数据丢失 | 立即修复，热修 |
| **S2 严重** | 单模块不可用、越权、会签/库存错误 | 当前迭代修复 |
| **S3 一般** | UI 错位、文案、非主路径 | 排期修复 |
| **S4 建议** | 体验优化 |  backlog |

### 9.2 缺陷单必填字段

- 环境（线上/预发/本地）
- 账号角色
- 复现步骤（含 URL / SN / 单号）
- 预期 vs 实际
- 截图/录屏
- 是否破坏演示数据

### 9.3 修复验证（Closed Loop）

```
发现 → 记录缺陷 ID
  → 开发修复 + 部署说明
  → 测试按原步骤回归（含关联模块）
  → 通过 → 关闭
  → 未通过 → 重开 + 回归清单追加该用例
```

### 9.4 发版回归包（最小集，约 45～60 分钟）

1. `GET /api/health` 200  
2. admin 登录 → 侧栏 16 项逐一点进（弹框即关）  
3. admin2 登录 → 停用会签弹框 → 稍后处理  
4. ops 登录 → 菜单 + `/system/roles` 拦截  
5. 一级详情 → 退货/采购待处理 → 返回  
6. 二级详情 → 「采购」→ 销售分销 tab  
7. 异常页 → 离开确认 → 暂不处理  
8. 角色页 → 三弹框取消；admin 不可停用  
9. 小程序：agent_hd / agent_hz / hd_scan_01 各登录首页  
10. SUB 扫码但不能 confirm（API 或 UI 二选一验证）

### 9.5 测试完成签字标准

| 角色 | 签字条件 |
|---|---|
| **测试** | P0/P1 用例执行率 100%；S1/S2 为 0 或已认可遗留 |
